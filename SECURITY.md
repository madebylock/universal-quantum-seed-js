# Security Policy

Universal Quantum Seed handles recovery phrases, key derivation, and
cryptographic key material. Please report suspected vulnerabilities privately
and use only synthetic fixtures when reproducing an issue.

## Supported versions

Security fixes are applied to the active development branch and the latest
supported release line. Until an independently reviewed release is announced,
development builds are pre-release software and must not be relied on as the
sole protection for production funds or sensitive accounts.

## Report a vulnerability privately

Do not open a public issue, discussion, or pull request for a suspected
vulnerability. Use the repository's **Security** tab and choose **Report a
vulnerability** to create a private GitHub Security Advisory. If private
reporting is unavailable, ask the Lock maintainers through a previously
established private organization channel for a secure reporting path. Do not
send exploit details through a public channel.

Include the affected commit, realistic prerequisites and impact, minimal
reproduction steps, and any suggested mitigation. Never include a real seed,
passphrase, private key, user record, production log, or wallet database.

## Research boundaries

Do not access another person's data, move funds, degrade a service, create
billable resources, perform denial of service, or use social engineering. Stop
testing and report immediately if real secret material is encountered.

This repository does not promise a bug bounty. Disclosure timing and any
recognition are coordinated case by case.
